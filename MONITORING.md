# Program monitoring

The Railway `program-monitor` cron service runs `npm run monitor:daily` hourly in UTC. Each program defaults to a **24-hour** cadence; the worker selects only due enabled programs. The hourly dispatcher also respects admin-configured shorter cadences. Monitoring never depends on page visits. The worker and web service are configured directly in Railway and use the same repository and database; reference settings are retained under `deploy/`. The worker exits after every run.

Run-level PostgreSQL advisory locking, unique hourly run keys, run leases, and per-program leases prevent concurrent duplicate checks. Expired leases can be reclaimed. Runs record queued/checked/updated programs, changes, manual reviews, failures, and completion state.

Source priority: official referral page, official terms, official help, supported API/feed, reviewed admin source, other evidence. Sources needing login are marked unavailable. Retrieval checks robots.txt, approved HTTPS domains, public DNS, maximum size/time, content type, redirects, and access-protection responses. It does not bypass controls. Per-host serialization/delay, bounded concurrency and retries/backoff limit load. DNS validation pins the public address for the connection. The generic adapter uses conservative structured extraction (`refermarket-public-offer-v1` JSON); ordinary HTML is hashed/summarized and queued when rewards cannot be safely extracted. It does not guess rewards from arbitrary dollar amounts.

HIGH-confidence small numeric reward changes from eligible official structured sources can publish automatically. Qualification, terms, permissions, URL, discontinuation, large rewards, medium/low confidence, and source conflicts require manual review. Demo observations always require review and never populate the real retrieval timestamp. Admins can check a program now, change cadence/priority, pause monitoring, add/update official sources, mark a source unreliable, edit candidate facts, and approve/reject candidates.

Offer facts are append-only. Publishing closes the previous version and advances the current pointer; geographic scopes remain separate from PUBLIC. Terms snapshots retain hashes, short summaries, structured changes, and timestamps. Source snapshots record status/confidence/failure without storing unnecessary full pages. Database triggers protect histories. Targeted offers never overwrite public offers.

The admin Monitoring tab shows runs, failures, source status, stale schedules, change reviews, and private targeted proof. Public program pages show verification/freshness, source, failed re-verification notices, and reviewed history. Candidate official URLs imported for known brands are unverified until retrieved. Their marketplace eligibility remains UNKNOWN.

Fictional `demo://` adapters support stable/increase/terms/failure/ended/location examples. These are labeled and do not contact websites. True production reward extraction requires a reviewed official structured source, program-specific parser or partner integration; generic HTML often requires manual review. On environments with restricted egress, allow the exact official domains through the supported environment policy. Railway’s scheduled worker has its own outbound connectivity; inspect actual run results before claiming checks succeeded.
