# Program monitoring

The Railway `program-monitor` cron service runs `npm run monitor:daily` hourly in UTC. Each program defaults to a **24-hour** cadence; the worker selects only due enabled programs. The hourly dispatcher also respects admin-configured shorter cadences. Monitoring never depends on page visits. The worker and web service are configured directly in Railway and use the same repository and database; reference settings are retained under `deploy/`. The worker exits after every run.

Run-level PostgreSQL advisory locking, unique hourly run keys, run leases, and per-program leases prevent concurrent duplicate checks. Expired leases can be reclaimed. Runs record queued/checked/updated programs, changes, manual reviews, failures, and completion state.

Source priority: official referral page, official company offer page, official terms, official help, supported API/feed, reviewed admin source, other evidence. Sources needing login are marked unavailable. Retrieval checks robots.txt, approved HTTPS domains, public DNS, maximum size/time, content type, redirects, and access-protection responses. It does not bypass controls. Per-host serialization/delay, bounded concurrency and retries/backoff limit load. DNS validation pins the public address for the connection. The generic adapter uses conservative structured extraction (`refermarket-public-offer-v1` JSON) or a configured, evidence-grounded AI provider after a meaningful hash change. Ordinary HTML is queued for review when credentials are absent or rewards cannot be safely extracted. It does not guess rewards from arbitrary dollar amounts.

HIGH-confidence small numeric reward changes from eligible official structured or quote-grounded AI sources can publish automatically. Qualification, terms, permissions, URL, discontinuation, large rewards, medium/low confidence, and source conflicts require manual review. Demo observations always require review and never populate the real retrieval timestamp. Admins can check a program now, change cadence/priority, pause monitoring, add/update official sources, mark a source unreliable, edit candidate facts, and approve/reject candidates.

Offer facts are append-only. Publishing closes the previous version and advances the current pointer; geographic scopes remain separate from PUBLIC. Terms snapshots retain hashes, short summaries, structured changes, and timestamps. Source snapshots record status/confidence/failure without storing unnecessary full pages. Database triggers protect histories. Targeted offers never overwrite public offers.

The admin Monitoring tab shows runs, failures, source status, stale schedules, change reviews, and private targeted proof. Public program pages show verification/freshness, source, failed re-verification notices, and reviewed history. Candidate official URLs imported for known brands are unverified until retrieved. Their marketplace eligibility remains UNKNOWN.

Fictional `demo://` adapters support stable/increase/terms/failure/ended/location examples. These are labeled and do not contact websites. True production reward extraction requires a reviewed official structured source, configured validated AI extraction, program-specific parser, or partner integration. AI/search credentials remain optional and absent until the owner supplies them; ambiguous generic HTML requires manual review. On environments with restricted egress, allow the exact official domains through the supported environment policy. Railway’s scheduled worker has its own outbound connectivity; inspect actual run results before claiming checks succeeded.

## Hybrid extraction and search

A retrieved page gets both a raw snapshot SHA-256 and a normalized meaningful-text SHA-256. Script/style/comment and whitespace changes do not trigger AI. An unchanged normalized hash reuses the prior extraction with a new retrieval snapshot and last-check timestamp; it does not call AI or create another candidate/history version. Terms histories append only when meaningful terms change. Changing provider/model or enabling a previously unconfigured provider invalidates that extraction cache. Failed/over-budget extraction can retry at the next due check. Public facts are never cleared because a page omits them.

`AIExtractionProvider` and `OfficialSearchProvider` in `src/lib/monitoring/providers.ts` are replaceable interfaces. The included AI adapter uses an OpenAI-compatible chat-completions endpoint. Supply `MONITOR_AI_PROVIDER=openai-compatible`, `MONITOR_AI_API_KEY`, `MONITOR_AI_MODEL`, and optionally `MONITOR_AI_ENDPOINT` (default `https://api.openai.com/v1/chat/completions`). Requests have a 25-second timeout, bounded input/output, JSON validation, and no tool use. Page text is untrusted data, never model instructions. Only retrieved public company sources are sent; private targeted proof, account details, and payment data are never sent.

The extraction schema includes signup/referrer descriptions, numeric amounts with explicit units and exact quotes, requirements, expiration, yes/no/unclear permission verdicts, targeted-offer possibility, restrictions, source URLs, evidence, and a 0–1 confidence score. Unknown facts stay null/unclear in extraction and are omitted from updates. Source URLs must equal the actual retrieved official URL. Unsupported quotes/amounts lower confidence and are dropped. Numeric values must match the quoted amount/unit. AI-reported confidence is not independent verification. Initial/ambiguous changes, permission/eligibility/legal/terms changes, conflicting sources, and large changes always require review. Only grounded HIGH-confidence small numeric changes from official referral/offer/structured sources can auto-publish. Permission verdicts never grant marketplace eligibility automatically; administrators still explicitly approve program permissions.

Source priority is official referral page → official offer page → official terms → official help → approved API/feed → reviewed admin/other evidence. Blogs, Reddit, affiliates, and code directories cannot become authoritative automatic sources.

For broken/missing/redirected official URLs, `MONITOR_SEARCH_PROVIDER=tavily` with `MONITOR_SEARCH_API_KEY` enables domain-restricted Tavily search (endpoint defaults to `https://api.tavily.com/search`). `MONITOR_SEARCH_PROVIDER=json` supports an alternative HTTPS endpoint accepting POST `{query,domain,max_results}` and returning `{results:[{url,title}]}`; provide `MONITOR_SEARCH_ENDPOINT` and its API key. Search results are not facts. Only approved-host HTTPS candidates that pass actual robots, DNS, retrieval, and content validation are stored, disabled pending admin product/source approval. Login/protected/private/unofficial results are discarded. Robots/bot/auth denials do not initiate search to bypass access rules. The original source URL and public facts stay preserved.

Default per-run limits are 10 AI calls and 3 search calls, adjustable using `MONITOR_AI_MAX_CALLS_PER_RUN` (0–100) and `MONITOR_SEARCH_MAX_CALLS_PER_RUN` (0–20). Per-source unchanged hashes skip extraction; shared limits apply across concurrent checks. API failures and exhausted budgets become reviewable statuses, never fabricated successful extraction.

The Monitoring admin tab reports checked/changed/error/review counts, unavailable URLs, low-confidence checks, last fully successful batch, next hourly dispatcher, provider configuration, field-by-field previous/detected values, confidence/method/source/time/status, and current/prior versions. Discovered sources need the explicit "Enable reviewed official source" action. Targeted rewards shown publicly come only from reviewed, valid, active listings; private evidence remains private and rewards are grouped by currency rather than combined into invented cash values.

No AI/search API keys are committed or provisioned automatically. Without them, actual official retrieval/hashes/history still work, unstructured data needs manual review, and discovery is explicitly NOT_CONFIGURED. Fictional demo adapters remain labeled simulations and never populate real retrieval timestamps.

Changing non-cash reward units or amounts clears inherited dollar-value estimates unless an administrator supplies a new estimate. Publishing a smaller/unvalued public reward pauses public listings whose bounties exceed its verified cash cap; targeted listings keep their own separate reviewed economics. Accepted referral amounts and historical versions are preserved. Serializable bid/payment retries use short bounded backoff to avoid repeated contention.
